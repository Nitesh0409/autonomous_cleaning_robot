VISION-BASED AUTONOMOUS CLEANING ROBOT SIMULATION
PROJECT STATUS AND SYSTEM ARCHITECTURE

I. PROJECT OBJECTIVE
The Vision-Based Autonomous Cleaning Robot Simulation project focuses on the development of an intelligent robotic system for maintaining complex indoor environments. The primary goal is to achieve reliable, collision-free navigation where the mobile platform can identify and collect debris while navigating through fields of both static and dynamic obstacles. This work ensures that the robot can operate autonomously at high speeds without compromising safety or efficiency.

II. HARDWARE AND PERCEPTION SETUP
A. Dual-LiDAR Configuration
To address the critical need for situational awareness, the robot is equipped with two high-precision LiDAR sensors located at the front and rear of the chassis. This dual configuration allows for a complete 360-degree field of view, successfully eliminating the blind spots common in single-sensor robot designs. This setup is particularly effective for holonomic maneuvers, such as sideways strafing and reversing, ensuring that obstacles are detected regardless of the robot's movement direction.

B. Vision Integration
In addition to the laser scanners, the platform integrates a front-facing RGB camera to facilitate visual data acquisition for automated cleaning tasks. This camera works in tandem with the LiDAR suite to provide a multi-modal perception system for both high-resolution object identification and long-range proximity sensing.

III. NAVIGATION AND PLANNING STRATEGY
A. Global Pathfinding
Global navigation is handled by an optimized A* algorithm. This system generates high-level waypoints by analyzing the environment grid, providing the most efficient route from the robot's current position to its intended goal.

B. Local Planning: Transition to DWA
While the project initially utilized an Artificial Potential Field (APF) approach for local obstacle avoidance, we have transitioned to the Dynamic Window Approach (DWA). This shift was driven by the need for better kinematic fluidity. DWA allows the robot to search for the best velocities while staying within its physical acceleration limits, leading to much smoother movement. Unlike the earlier force-based APF models, DWA uses predictive trajectory simulation to avoid collisions and is significantly more robust against getting trapped in local minima, such as U-shaped dead ends.

IV. PROJECT ORGANIZATION AND FILE STRUCTURE
The repository is organized following standard ROS 2 package conventions to ensure modularity and ease of deployment. The core logic and assets are distributed across the following directories:

A. robot/
This directory serves as the brain of the system. it contains the A* Global Planner and the Nitro-DWA Local Planner. It also houses the mission management logic and the centralized robot UI dashboard, which coordinates the cleaning cycles and provides real-time telemetry.

B. config/ and launch/
The config folder contains the RViz visualization profiles and bridge configurations that link the ROS 2 environment with the Gazebo simulation. The launch directory contains Python orchestrator scripts that automate the simultaneous initialization of the robot nodes, the bridge, and the simulation interface.

C. models/ and meshes/
These directories contain the physical definitions of the robot. The models folder houses the URDF descriptions of the holonomic chassis and manipulator arms, while the meshes folder contains the 3D geometry for components like the mecanum wheels, ensuring accurate physics and visual representation in the simulation.

D. worlds/
The worlds directory contains the varied simulation environments, ranging from static obstacle fields to dynamic arenas with moving actors. These environments are essential for rigorously validating the performance of the navigation stack under different stress levels.
